## F1 — `tests/test_backup_db.py::test_snapshot_failure_is_logged_not_raised`
не привязан к бэкенду, хотя должен быть

При запуске полного набора тестов против настоящего PostgreSQL (что
требовалось для проверки Phase 1) этот тест либо падает, либо проходит по
неверной причине — он monkeypatch'ит `Command._backup_sqlite`, ожидая, что
именно этот путь вызовется и «сломается». Под Postgres реально вызывается
`_backup_postgres`, так что patch — no-op, и тест либо молча не проверяет
то, что должен, либо падает с `assert "FAILED" in ""` в зависимости от
деталей окружения.

Его сосед в том же файле, `test_sqlite_snapshot_is_a_real_openable_copy_of_the_data`,
уже правильно помечен:
```python
@pytest.mark.skipif(
    "sqlite" not in connection.settings_dict["ENGINE"], reason="sqlite-only snapshot content check"
)
```
`test_snapshot_failure_is_logged_not_raised` — очевидно того же рода (тестирует
sqlite-специфичный путь через monkeypatch конкретного sqlite-метода), но
такой пометки не имеет. Скорее всего, простая недоработка при написании
теста, а не намеренное решение.

**Почему не исправлено сейчас**: `tests/test_backup_db.py` не входит ни в
одну из перечисленных находок (H1/H2/M1-M3/L1-L5) — это отдельный, более
простой механизм снапшотов (`manage.py backup_db`), не тот код, который
Phase 1 трогает. Однократная строка (`@pytest.mark.skipif(...)`, тот же
паттерн, что уже есть двумя тестами выше) — тривиальное исправление, но
вне периметра этой сессии.

**Как это повлияло на прогон Phase 1**: полный набор тестов был реально
прогнан против настоящего Postgres (не SQLite) по правилу сессии. Под
обычным `config.settings.test` (SQLite, как тесты запускаются по
умолчанию) — весь набор зелёный, эта проблема не проявляется. Против
Postgres — эта ОДНА строка требует ручного объяснения при чтении результата;
не связана ни с одним изменением этой сессии (файл не редактировался).

**Предлагаемое исправление** (не применено, ждёт решения): добавить тот же
`@pytest.mark.skipif` над `test_snapshot_failure_is_logged_not_raised`,
что уже стоит над соседним тестом в этом же файле.
